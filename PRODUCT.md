# Product

## Register

product

## Users

Developers who run Symphony locally to coordinate coding agents across one or more repositories. They use the dashboard as a quick operational scan between development tasks: what is running, what needs attention, what is queued, and where to open the underlying GitHub issue, pull request, workspace, or agent output.

## Product Purpose

Symphony is a simple GitHub-issues-driven agent orchestrator for everyday software development. The dashboard makes its readonly runtime state legible without turning Symphony into a project-management suite. Success means a developer can understand system health, locate blocked work, and reach supporting evidence within seconds.

## Brand Personality

Calm, precise, and trustworthy. The interface should feel like a focused local developer tool: capable without being theatrical, dense without becoming cramped, and opinionated without inventing unfamiliar interactions.

## Anti-references

- Dark mission-control dashboards with neon status colors, glass effects, or decorative monitoring chrome.
- Full project-management systems that bury orchestration state beneath navigation, configuration, and reporting features.
- Generic SaaS card galleries, oversized vanity metrics, and ornamental gradients.
- Interfaces that rely on color alone to communicate status or make local paths and debugging evidence difficult to reach.

## Design Principles

- Lead with operational attention: running, blocked, stale, and review states should be recognizable at a glance.
- Keep the system small: improve scanning and evidence access before adding new dashboard concepts.
- Preserve trustworthy detail: issue links, PR links, timestamps, errors, and artifact paths remain available close to the task.
- Use familiar product patterns: standard filters, keyboard-operable disclosure, clear focus states, and predictable responsive behavior.
- Make quiet states quiet: reserve visual weight and semantic color for work that needs attention.

## Accessibility & Inclusion

Target WCAG 2.2 AA contrast and keyboard operation. Never rely on color alone for status. Respect reduced-motion preferences, preserve visible focus indicators, use semantic landmarks and labels, and keep text readable at browser zoom and narrow viewport widths.
